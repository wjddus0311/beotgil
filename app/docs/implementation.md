# React Native 앱 설계 및 구현 계획

목표: 웹앱의 지도 중심 UI, 노란색 강조색, 펼치는 하단 패널, 길찾기/건의사항 메뉴를 iOS·Android 네이티브 앱으로 제공한다. 모든 신규 파일은 app/에 둔다.

선택: Expo + React Native + react-native-maps. 지도는 iOS Apple Maps, Android Google Maps를 사용하고 장소 검색·경로는 기존 카카오 서버를 재사용한다. WebView로 웹 전체를 감싸는 방식은 네이티브 화면 요청에 맞지 않고, 카카오 네이티브 SDK 도입은 별도 플랫폼 연동 비용이 크다. Android 배포에는 Google Maps 키가 필요하다.

책임: src/domain.ts는 장소 검증과 경로 응답 해석, src/api.ts는 HTTP 오류/시간제한, src/usePlaces.ts는 기기 저장, src/*Panel.tsx는 입력·안내, App.tsx는 지도와 패널 연결을 맡는다. server.py는 기존 BeotgilHandler를 상속하고 /api/places만 추가한다. 서버의 저장·인증·외부 API 정책은 그대로 재사용한다.

불변 조건: 입력을 수정하면 선택 좌표와 경로를 무효화한다. 이전 요청은 새 선택 결과를 덮어쓰지 않는다. REST 키는 서버에만 둔다. 장소 검색은 달성군 결과만 허용한다. 경로/시설/대피소 데이터는 휠체어 안전 판정이 아니다. 정보 0건을 접근성 보장으로 표시하지 않는다. 저장 실패·위치 권한 거절·API 장애는 사용자에게 알린다. 건의 내용은 공유 서버에 저장됨을 알린다.

범위: 출발/도착 검색과 현재 위치, 일반 도보 안내와 위험 키워드, 도보 10분 이상 대체 교통 시간과 경로, 저장/최근 장소, 편의시설 및 정정, 건의 등록/목록, 대피소 종류별 조회와 가까운 5곳 도보 비교, 지도 범위 계단/경사로 조회. 로그인·실시간 내비게이션·휠체어 안전 경로 계산·앱스토어 배포는 추가하지 않는다.

실행 순서:
- [x] 장소/경로 검증 테스트, API 장소 검색 테스트를 먼저 작성하고 모듈 미구현 실패 확인.
- [x] Expo 호환 의존성 설치, 데이터 처리 및 서버 확장 구현.
- [x] 네이티브 지도/패널/기기 저장/위치/신고 흐름 구현.
- [x] 타입 검사, Node/Python 테스트, iOS·Android JS 번들 생성, 변경 검토.

검증 초점: 잘못된 좌표와 응답, 입력 변경 중 응답 도착, 저장 실패, 권한 거절, 교통 경로 좌표 누락. 실제 지도 타일·위치·공공 API는 키가 설정된 기기에서 별도 검증한다.

검증 결과: TypeScript 검사 통과, Node 테스트 7개와 Python 테스트 5개 통과. 임시 SQLite와 실제 로컬 HTTP로 건의/정정 API를 검증했다. iOS·Android JS/Hermes 번들 생성 통과. Expo 58 버전 호환 검사 통과. Xcode 시뮬레이터 도구가 없어 네이티브 빌드·기기 화면·키가 필요한 외부 API·위치 권한·기기 저장 장애·요청 중 입력 변경은 실제 기기 검증 전이다. 늦은 응답은 요청 번호/효과 정리로 무효화하도록 코드를 검토했다.

의존성: npm audit에 Expo fingerprint → minimatch의 중간 등급 경고 3건이 남는다(직접 취약점 1건과 영향 패키지 2개). 빌드 도구의 파일 패턴 처리 관련이며 앱의 길찾기 처리에는 사용하지 않는다. 자동 수정 제안은 구형 SDK로의 주요 버전 변경이므로 적용하지 않았다. 상위 도구의 수정 버전이 나오면 갱신한다.

## 패널 열기/닫기 변경

초기 패널은 닫힘이다. 하단 메뉴는 패널을 토글하는 버튼이며 현재 열린 패널의 버튼만 활성 표시한다. 다른 버튼은 클릭 가능한 비선택 상태다. 같은 버튼 재클릭, 닫기, Android 뒤로가기로 닫을 수 있다. 열림/닫힘은 슬라이드 애니메이션을 사용하며 닫힌 패널은 터치와 접근성 탐색에서 제외한다. 지도 버튼과 가로 화면 검색창 위치도 패널 표시 여부에 맞춘다. 입력 상태는 유지한다.

`src/sheet.ts`에서 닫힘·열림·전환·크기 변경을 처리한다. 상태 전환 테스트 4개를 추가했고 Node 테스트 총 11개 및 타입 검사를 통과했다. 실제 기기 애니메이션과 터치/스크린리더 동작은 미검증이다.
